# Известные ограничения и открытые технические вопросы (KNOWN_ISSUES)

В этом документе фиксируются текущие архитектурные ограничения, нерешённые краевые случаи спецификации и известные проблемы реализации по мере продвижения проекта.

---

## Текущие ограничения архитектуры и спецификации (Этап 1)

1. **Циклические графы владения вне регионов (`KI-001`):**
   - В модели одиночного владения (`Managed Ownership`) запрещено создание циклов сильных ссылок. Для построения произвольных графов с циклами программист обязан использовать либо блочную область памяти `region` с дескрипторами `RegionHandle<T>`, либо разделяемые указатели со слабыми ссылками (`Shared<T>` / `Weak<T>`).
2. **Возврат невладеющих ссылок из функций с несколькими источниками (`KI-002`):**
   - Если функция принимает несколько параметров `read T` и возвращает ссылочное представление, анализатор AMA без явных меток источника консервативно связывает время жизни результата с пересечением времён жизни всех входных параметров `read` совместимого типа.
3. **Динамическая проверка границ при индексации (`KI-003`):**
   - Индексация массивов и векторов `arr[i]` выполняет проверку границ во время выполнения, если оптимизатор (Range Analysis) не смог статически доказать условие `0 <= i < len`.
4. **Зависимость кодогенерации от системного тулчейна LLVM (`KI-004`):**
   - Для сборки нативных исполняемых файлов из сгенерированного LLVM IR требуется наличие в системе компилятора `clang` (рекомендуется LLVM 22+, на текущей рабочей станции обнаружен `C:\Program Files\LLVM\bin\clang.exe` версии 22.1.8).
5. **Кросс-компиляция на macOS ARM64 с хоста Windows (`KI-005`):**
   - Генерация целевого LLVM IR для `aarch64-apple-darwin` и `x86_64-unknown-linux-gnu` полностью поддерживается и проверяется компилятором, однако финальная линковка и нативный запуск на хосте Windows x86-64 возможны непосредственно для `x86_64-pc-windows-msvc` (для остальных платформ предоставляются инструкции и проверка генерации машинного/объектного кода).
