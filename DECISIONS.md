# Архитектурные и технические решения APS (Architecture Decision Records)

В этом документе фиксируются ключевые инженерные решения, принятые командой разработки языка программирования **APS (Advanced Performance Systems)**.

---

## ADR-001: Выбор языка реализации компилятора и архитектуры пайплайна

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Для создания промышленного компилятора системного языка программирования необходима строгая типизация, высокая скорость работы самого компилятора, безопасность памяти и модульная архитектура промежуточных представлений.
- **Решение:**
  1. Реализовать компилятор `aps` на языке **Rust** (workspace/модульная архитектура).
  2. Построить многоуровневый собственный компиляторный конвейер (pipeline), не сводящийся к прямой трансляции AST в LLVM:
     `APS Source → Lexer → Parser → AST → Semantic Analysis → Type Checker → AMA Analysis → HIR → MIR → APS IR → Optimizer → LLVM Backend → Native Executable`.
  3. Использовать **LLVM** (через генерацию строго типизированного LLVM IR и вызов системного набора инструментов LLVM `clang` / `lld-link` версии 22+) в качестве кодогенератора машинного кода для целевых платформ (`x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`).
- **Причины:**
  - Наличие отдельных уровней HIR (десахаризация и разрешение имён/типов), MIR (граф потока управления CFG для анализа времени жизни, проверки инициализации и вставки деструкторов AMA) и APS IR (линейное SSA-представление для платформенно-независимых оптимизаций APS) позволяет проводить высокоуровневые оптимизации и проверки безопасности до передачи кода в LLVM.

## ADR-002: Модель памяти AMA (APS Adaptive Memory Architecture)

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Существующие языки делятся на два лагеря: языки со сборщиком мусора (Go, Java, C#), страдающие от пауз и непредсказуемого потребления памяти, и языки с ручным аннотированием времён жизни (Rust `'a`), создающие высокий порог входа и «шум» в сигнатурах при работе со сложными графами данных.
- **Решение:** Разработать четырёхуровневую архитектуру памяти **AMA (APS Adaptive Memory Architecture)**:
  1. **Local Memory (Stack Tier):** Автоматическое размещение локальных неизбегающих (non-escaping) объектов на стеке на основе Escape Analysis.
  2. **Managed Ownership (Single-Owner Heap Tier):** Каждый динамический объект имеет единственного владельца. Компилятор строит граф владения и автоматически вычисляет точки детерминированного освобождения памяти (Compile-Time Free Placement — CTFP) без участия GC.
  3. **Region Memory (`region` Tier):** Лексические и динамические области памяти (арены) с групповым выделением `O(1)` и мгновенным освобождением всей области при выходе из блока `region`. Компилятор статически гарантирует невыход ссылок за пределы региона (`E0305`).
  4. **Shared Immutable Memory (`shared` Tier):** Глубоко неизменяемые разделяемые объекты с атомарным подсчётом ссылок для безопасной передачи между потоками и `async`-задачами без гонок данных.

## ADR-003: Система прав доступа (Access Capabilities: `read`, `write`, `take`)

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Необходимо сделать передачу параметров в функции прозрачной, безопасной и самодокументируемой без сложных времён жизни `'a` в 95% пользовательского кода.
- **Решение:** Ввести три явные категории прав доступа (Access Capabilities) второго класса (second-class capabilities):
  - `read T` — временный невладеющий доступ только для чтения (допускается множество одновременных читателей, запрещена модификация и сохранение ссылки вне области вызова).
  - `write T` — эксклюзивный временный доступ для модификации (запрещено одновременное чтение или запись того же объекта; поддерживается раздельный доступ к непересекающимся полям структуры — Field-Disjoint Projection).
  - `take T` — передача владения объектом вызываемой функции (исходная переменная переходит в состояние `Moved`, повторное обращение к ней блокируется ошибкой `E0301`).
  - Для примитивных копируемых типов (`CopyValue`: числа, `bool`, `char`) передача по значению копирует биты без инвалидации источника.

## ADR-004: Запрет циклических графов в одиночном владении и решение через Regions / Weak

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Без сборщика мусора произвольные циклы сильных ссылок приводят к утечкам памяти.
- **Решение:**
  1. Одиночное владение (`Managed Ownership`) образует строго ориентированный ациклический граф (DAG / дерево владения).
  2. Для циклических структур данных (графы, двусвязные списки, DOM/AST с обратными ссылками) стандартным механизмом в APS являются **Regions (`region`)** с типизированными индексами/дескрипторами (`RegionHandle<T>`) либо явные слабые ссылки `Weak<T>` в паре с `Shared<T>`.

## ADR-005: Синтаксис без визуального шума и строгая типизация

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Синтаксис должен быть лаконичным, легко читаемым и однозначно разбираемым парсером за линейное время `O(n)`.
- **Решение:**
  - `let` — неизменяемая привязка, `var` — изменяемая привязка, `const` — константа времени компиляции.
  - Точки с запятой `;` опциональны (перевод строки завершает инструкцию, если токен допускает завершение инструкции).
  - Строгая статическая типизация без неявных сужающих приведений числовых типов (запрещено неявное `i64 -> i32` или `i64 -> f64`, требуется явный оператор `as`).
  - Обработка ошибок через алгебраические типы `Result<T, E>` и `Option<T>` с оператором проброса `?`, без скрытых раскруток стека (exceptions).

## ADR-006: Интеграция Runtime и границы безопасности FFI

- **Статус:** Принято
- **Дата:** 2026-11-07
- **Контекст:** Языку без GC всё равно необходим минимальный системный рантайм для аллокации памяти, работы с регионами, строками, коллекциями, потоками, сетевым вводом-выводом и обработкой фатальных паник.
- **Решение:**
  - Выделить минимальный детерминированный рантайм (линкуемый в исполняемый файл без накладных расходов GC).
  - Любое взаимодействие с внешним C ABI (`extern "C"`) требует явного блока или модификатора `unsafe` и проверки инвариантов на границе вызова.
