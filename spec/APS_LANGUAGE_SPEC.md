# Полная техническая спецификация языка программирования APS (Advanced Performance Systems)

**Версия спецификации:** 1.0 (Этап 1)  
**Статус:** Утверждена для реализации компилятора  

---

## 0. Предварительное исследование современных языков и компиляторов

При проектировании APS проведён сравнительный инженерный анализ существующих системных и прикладных языков программирования:

| Язык / Инструмент | Сильные стороны, учтённые в APS | Слабые стороны, устранённые в APS |
|---|---|---|
| **Rust** | Нулевая стоимость абстракций, отсутствие GC, алгебраические типы (`enum`, `Result`, `Option`), сопоставление с образцом (`match`). | Сложность явных времён жизни `'a`, трудности построения графов и ареновых структур данных, шумный синтаксис времён жизни. В APS заменено на **AMA** (`read`/`write`/`take` + `region` + `shared`). |
| **C / C++** | Прямой контроль над размещением данных в памяти, предсказуемый ABI, минимальный рантайм, высокая скорость машинного кода. | Отсутствие безопасности памяти по умолчанию (UAF, double-free, переполнение буфера, неинициализированная память, гонки данных). В APS полностью блокируется на этапе компиляции. |
| **Zig** | Прозрачность потока управления, отсутствие скрытых аллокаций, мощное выполнение на этапе компиляции (`comptime`), явная работа с аренами. | Отсутствие полной статической верификации висячих указателей в безопасном подмножестве. В APS регионы (`region`) статически проверяются на невыход ссылок (`Escape Analysis`). |
| **Swift** | Читаемые модификаторы параметров (`borrowing`, `inout`, `consuming`), эргономичный синтаксис без обязательных `;`. | Повсеместный атомарный подсчёт ссылок (ARC) создаёт накладные расходы в циклах и многопоточном коде. В APS одиночное владение детерминированно освобождается без ARC, а подсчёт ссылок используется только при явном запросе `share(...)`. |
| **Go** | Простота чтения кода, быстрая компиляция, понятная модель конкурентности (каналы и задачи). | Обязательный сборщик мусора (GC), паузы латентности, отсутствие полноценных алгебраических типов и защиты от `nil`-паник. |
| **LLVM / GCC** | Промышленная кодогенерация, векторизация SIMD, межпроцедурные оптимизации (LTO, инлайнинг, SROA). | Низкоуровневый IR не знает о высокоуровневых инвариантах владения и регионов APS — поэтому APS реализует собственные уровни `HIR → MIR → APS IR` перед передачей в LLVM. |

## 1. Философия языка

**APS (Advanced Performance Systems)** — статически типизированный компилируемый язык системного и высокопроизводительного прикладного программирования.

Формула философии APS:
> **Эргономика чтения и написания кода + строгая статическая безопасность памяти без GC + максимальная производительность машинного кода + детерминированный контроль над системными ресурсами.**

Фундаментальные принципы:
1. **Нулевая стоимость безопасности по умолчанию:** проверки прав доступа (`read`, `write`, `take`), графа владения и времён жизни регионов выполняются компилятором статически и не добавляют инструкций во время выполнения.
2. **Явность вместо скрытой магии:** в языке нет скрытых сборщиков мусора, неявных копирований тяжёлых структур или скрытых исключений (`exceptions`).
3. **Адаптивность памяти (AMA):** программист выбирает (или компилятор автоматически выводит) оптимальный уровень памяти под задачу: стек (`Local`), одиночное владение в куче (`Managed Ownership`), быстрая групповая арена (`region`) или потокобезопасное неизменяемое разделение (`shared`).
4. **Отсутствие `null` в безопасном коде:** отсутствие значения всегда выражается типом `Option<T>`.

## 2. Общие правила синтаксиса

- Исходные файлы APS имеют расширение `.aps` и кодируются в UTF-8.
- Блоки кода ограничиваются фигурными скобками `{` и `}`.
- Точка с запятой `;` в конце инструкции **опциональна**: перевод строки автоматически завершает инструкцию, если текущий токен может быть концом инструкции (идентификатор, литерал, `return`, `break`, `continue`, закрывающая скобка `)`, `]`, `}`). Несколько инструкций на одной строке разделяются `;`.
- Блок `{ ... }` может выступать как выражением: значением блока является его последнее выражение.
- Комментарии:
  - Однострочные: `// комментарий до конца строки`
  - Многострочные (поддерживают вложенность): `/* комментарий */`
  - Документирующие: `/// документация элемента` и `//! документация модуля`

## 3. Переменные

В APS различаются неизменяемые и изменяемые привязки:

### 3.1. Неизменяемые переменные (`let`)
По умолчанию переменные неизменяемы после инициализации:
```aps
let age: i32 = 15
let name = "Alibek" // тип String выводится автоматически
```
Попытка повторного присваивания переменной `let` или передачи её как `write` вызывает ошибку компиляции `E0204` / `E0042`.

### 3.2. Изменяемые переменные (`var`)
Для разрешения модификации значения или перепривязки используется ключевое слово `var`:
```aps
var balance: i64 = 1000
balance += 500
```

### 3.3. Правила инициализации
- В безопасном коде APS запрещено чтение неинициализированных переменных (`E0307`).
- Затенение (shadowing) имён внутри одного блока разрешено через повторное объявление `let`, но затенение имени переменной вложенным блоком с тем же именем сопровождается предупреждением линтера при риске неоднозначности.

---

## 4. Константы

Константы объявляются ключевым словом `const` и обязаны быть вычислимыми на этапе компиляции:
```aps
const MAX_CONNECTIONS: i64 = 10000
const PI: f64 = 3.141592653589793
const BUFFER_SIZE: usize = 64 * 1024
```
- Константы могут объявляться как на уровне модуля, так и внутри функций.
- Константы не занимают изменяемой памяти в рантайме и подставляются (inlined) непосредственно в точки использования.

---

## 5. Базовые типы

Система базовых типов APS включает:
- `bool` — логический тип (`true` или `false`), размер 1 байт.
- `char` — скалярное значение Unicode (UTF-32 code point, 4 байта), записывается в одинарных кавычках: `'A'`, `'Я'`, `'\n'`.
- `void` (или `()`) — единичный пустой тип для функций, не возвращающих полезного значения.
- `never` (`!`) — пустой тип для выражений, которые никогда не возвращают управление (`return`, `break`, `panic(...)`).

Базовые примитивные типы реализуют встроенное свойство `Copy` (побитовое копирование при присваивании и передаче в функции без перемещения владения).

---

## 6. Числовые типы

| Категория | Типы | Описание |
|---|---|---|
| Знаковые целые | `i8`, `i16`, `i32`, `i64`, `isize` | Дополнительный код (two's complement). `isize` равен разрядности указателя целевой архитектуры (64 бита на x86-64/ARM64). |
| Беззнаковые целые | `u8`, `u16`, `u32`, `u64`, `usize` | Диапазон от `0` до $2^N - 1$. `usize` используется для индексации и размеров в памяти. |
| Числа с плавающей точкой | `f32`, `f64` | Стандарт IEEE 754 (одинарная и двойная точность). |

### Правила числовых литералов и операций:
- Тип целочисленного литерала без суффикса по умолчанию выводится из контекста, а при отсутствии ограничений принимается равным **`i64`**.
- Тип вещественного литерала по умолчанию — **`f64`**.
- Поддерживаются префиксы систем счисления: `0x` (шестнадцатеричная), `0b` (двоичная), `0o` (восьмеричная) и разделитель разрядов `_` (например, `1_000_000`).
- **Запрет неявных приведений:** сложение `i32 + i64` или `i64 + f64` без явного преобразования `x as i64` или `x as f64` является ошибкой типизации `E0101`.
- Целочисленное переполнение в режиме отладки вызывает детерминированную панику, а для модульной или насыщающей арифметики предоставляются явные методы (`wrapping_add`, `saturating_add`, `checked_add`).

## 7. Строки

В APS предусмотрены два основных строковых представления:
1. **`String`** — владеющая динамическая строка в кодировке UTF-8 (тройка `{ ptr, len, cap }`), управляемая системой памяти AMA (автоматически освобождается при выходе владельца из области видимости).
2. **`str`** (передаётся как `read str` или `read String`) — невладеющее представление (срез `{ ptr, len }`) последовательности валидных байтов UTF-8.

```aps
let greeting: String = "Привет, APS!"
let length = greeting.len()
```
Поддерживаются строковые операции: конкатенация `+`, сравнение `==`, `!=`, взятие длины `.len()`, проверка подстрок `.contains(...)`, разбиение `.split(...)`, тримминг `.trim()`.

---

## 8. Массивы

### 8.1. Статические массивы фиксированной длины `[T; N]`
Размещаются непосредственно на стеке или внутри структуры без аллокации в куче:
```aps
let vector3d: [f64; 3] = [1.0, 2.5, -0.5]
let first = vector3d[0]
```

### 8.2. Динамические массивы и срезы `[T]`
Литерал `[10, 20, 30, 40]` создаёт индексируемую последовательность элементов одного типа.
Доступ по индексу `arr[idx]` проверяет границы диапазона `0 <= idx < arr.len()`. При выходе за границы в рантайме возбуждается защитная паника `R0001: index out of bounds` вместо чтения чужой памяти.

---

## 9. Коллекции

Стандартная библиотека `std.collections` предоставляет обобщённые контейнеры, полностью интегрированные с AMA:
- `Vec<T>` — динамический непрерывный массив в куче или регионе (`push`, `pop`, `len`, `get`, индексация `v[i]`).
- `HashMap<K, V>` — хеш-таблица с открытой адресацией (Robin Hood / SwissTable probing) и защитой от коллизий (`insert`, `get`, `contains_key`, `remove`).
- `HashSet<T>` — множество уникальных элементов.
- `Queue<T>` / `RingBuffer<T>` — кольцевая очередь `O(1)`.
- `Stack<T>` — стек LIFO.

Когда коллекция `Vec<T>` или `HashMap<K, V>` выходит из области видимости владельца, AMA автоматически вызывает деструкторы всех содержащихся элементов и освобождает буфер памяти.

## 10. Функции

Функции объявляются с помощью ключевого слова `fn`:
```aps
fn calculate(a: i64, b: i64) -> i64 {
    return a + b
}

// Эквивалентная краткая форма с результирующим выражением блока:
fn multiply(a: i64, b: i64) -> i64 {
    a * b
}
```
- Если возвращаемый тип не указан, он считается равным `void`.
- Точка входа исполняемой программы — функция `fn main()` (возвращающая `void` или `i32` / `Result<void, String>`).
- Параметры непримитивных типов принимают явные модификаторы прав доступа AMA: `read T` (по умолчанию для чтения), `write T` (для модификации), `take T` (для поглощения владения).

---

## 11. Структуры

Структуры (`struct`) объединяют именованные поля с фиксированным расположением в памяти:
```aps
struct Driver {
    id: i64
    name: String
    balance: i64
}

fn add_balance(driver: write Driver, amount: i64) {
    driver.balance += amount
}

fn show_driver(driver: read Driver) {
    println(driver.name)
}
```
Также поддерживаются блоки методов `impl Driver { ... }`, позволяющие вызывать функции через точечную нотацию `driver.add_balance(100)`:
```aps
impl Driver {
    fn new(id: i64, name: String, balance: i64) -> Driver {
        Driver { id: id, name: name, balance: balance }
    }

    fn deposit(self: write Driver, amount: i64) {
        self.balance += amount
    }

    fn info(self: read Driver) -> i64 {
        self.balance
    }
}
```

## 12. Перечисления (Enums)

Перечисления в APS являются полноценными алгебраическими типами данных (размеченными объединениями — tagged unions / sum types):
```aps
enum PaymentState {
    Pending
    Authorized(i64)
    Settled { tx_id: i64, fee: i64 }
    Rejected(String)
}
```
Каждому варианту компилятор назначает компактный дискриминант (тег), а размер всего `enum` равен размеру наибольшего варианта плюс выровненный тег.

---

## 13. Обобщённые типы (Generics)

APS поддерживает параметрический полиморфизм для структур, перечислений и функций с мономорфизацией на этапе компиляции (нулевые накладные расходы в рантайме, как в C++ и Rust):
```aps
struct Pair<T, U> {
    first: T
    second: U
}

fn swap_pair<T, U>(p: take Pair<T, U>) -> Pair<U, T> {
    Pair { first: p.second, second: p.first }
}
```
Ограничения обобщённых параметров задаются через интерфейсы/контракты (`trait` / `: Comparable`):
```aps
fn max_of<T: Comparable>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
```

## 14. Pattern Matching (Сопоставление с образцом)

Конструкция `match` обеспечивает исчерпывающий (exhaustive) разбор значений:
```aps
match state {
    PaymentState.Pending => {
        println("Ожидание оплаты")
    }
    PaymentState.Authorized(amount) => {
        println(amount)
    }
    PaymentState.Settled { tx_id, fee } => {
        println(tx_id)
    }
    PaymentState.Rejected(reason) => {
        println(reason)
    }
}
```
- Компилятор проверяет **полноту охвата (exhaustiveness)**: если хотя бы один вариант `enum` не обработан и отсутствует ветка по умолчанию `_ => ...`, выдаётся ошибка `E0104`.
- Поддерживаются литеральные образцы, диапазоны, деструктуризация структур и вариантов перечислений, а также связывание переменных.

---

## 15. Условия

Условная конструкция `if` / `else if` / `else` требует строго булевого выражения типа `bool` (неявное приведение числа `0` или указателя к `bool` запрещено):
```aps
if balance >= 1000 {
    println("VIP-тариф")
} else if balance > 0 {
    println("Стандартный тариф")
} else {
    println("Недостаточно средств")
}
```
`if` может использоваться как выражение:
```aps
let fee: i64 = if amount > 5000 { 0 } else { 50 }
```

---

## 16. Циклы

В APS предусмотрены три вида циклов:
1. **`while`** — цикл с предусловием:
   ```aps
   var i = 0
   while i < 10 {
       i += 1
   }
   ```
2. **`for`** — итерация по полуинтервалу `start..end` (или закрытому диапазону `start..=end`) и по коллекциям:
   ```aps
   for idx in 0..10 {
       println(idx)
   }
   ```
3. **`loop`** — безусловный бесконечный цикл с выходом по `break`:
   ```aps
   loop {
       if ready {
           break
       }
   }
   ```
Ключевое слово `break` досрочно завершает ближайший цикл, `continue` переходит к следующей итерации.

## 17. Обработка ошибок

В APS **нет неконтролируемых исключений (`try/throw/catch`)**. Все ожидаемые ошибки являются значениями и выражаются стандартными алгебраическими типами:

```aps
enum Option<T> {
    Some(T)
    None
}

enum Result<T, E> {
    Ok(T)
    Err(E)
}
```

### 17.1. Оператор проброса ошибки `?`
Выражение `expr?` проверяет результат `Result<T, E>` (или `Option<T>`):
- если значение равно `Ok(v)` (`Some(v)`), выражение вычисляется в `v`;
- если значение равно `Err(e)` (`None`), текущая функция немедленно выполняет все зарегистрированные деструкторы AMA и блоки `defer`, после чего возвращает `Err(e)` (`None`) вызывающей стороне.

### 17.2. Отложенное выполнение `defer`
Инструкция `defer { ... }` регистрирует блок кода, который гарантированно выполнится при выходе из текущей области видимости (в порядке LIFO) независимо от того, произошёл ли выход через обычный конец блока, `return` или оператор `?`.

## 18. Модули

Каждый файл `.aps` или каталог с файлом `mod.aps` образует модуль. Имя модуля может быть явно задекларировано в начале файла:

Иерархия модулей соответствует структуре каталогов проекта (`src/net/http.aps` → модуль `net.http`).

Подключение функциональности из стандартной библиотеки или других модулей выполняется директивой `import`:

## 20. Области видимости

- **Приватность по умолчанию:** все функции, структуры, поля структур, перечисления и константы внутри модуля по умолчанию приватны для этого модуля.
- **Публичный доступ (`pub`):** модификатор `pub` делает объявление доступным для внешних модулей (`pub fn`, `pub struct`, `pub enum`, `pub const`).
- **Лексическая область видимости в блоках:** переменные живут от точки объявления до закрывающей скобки `}` своего блока (если не были перемещены раньше через `take`).

## 21. Замыкания (Closures)

Анонимные функции (замыкания) записываются с использованием вертикальных черт `|...|`:
```aps
let multiplier: i64 = 3
let scale = |x: i64| -> i64 { x * multiplier }
let result = scale(14) // 42
```
Захват переменных окружения подчиняется правилам AMA:
- по умолчанию замыкание захватывает внешние переменные в режиме `read`;
- если замыкание модифицирует внешнюю переменную, оно требует `write`-доступа к ней на всё время жизни замыкания;
- если замыкание передаётся в другой поток или возвращается из функции (`move |...|`), захваченные значения перемещаются (`take`) внутрь структуры замыкания.

## 22. Работа с памятью

Память процесса в APS строго разделена на:
1. **Сегмент кода и констант (`.text` / `.rodata`):** скомпилированные инструкции и неизменяемые строковые/числовые константы.
2. **Стек вызовов (Stack):** кадры функций, локальные примитивы и локальные структуры, не покидающие функцию.
3. **Управляемая куча (Managed Heap):** динамические объекты с единственным владельцем, детерминированно освобождаемые компилятором в вычисленных точках `aps_free`.
4. **Региональные арены (Regions):** линейные блоки памяти со сверхбыстрым bump-аллокатором `O(1)` и мгновенным групповым сбросом при закрытии блока `region`.

В безопасном коде APS адресная арифметика над сырыми указателями запрещена.

## 23. Access Capabilities (`read`, `write`, `take`)

Модель прав доступа APS заменяет сложные аннотации времён жизни тремя фундаментальными режимами передачи данных:

| Модификатор | Семантика владения | Чтение | Модификация | Одновременные алиасы в точке вызова | Состояние переменной у вызывающего после вызова |
|---|---|---|---|---|---|
| `read T` | Временное заимствование | Разрешено | Запрещено (`E0042`) | Неограниченное число `read T` | Остаётся валидной (`Owned`) |
| `write T` | Эксклюзивное заимствование | Разрешено | Разрешено | Ни одного другого `read` или `write` к тому же корню/полю (`E0302`) | Остаётся валидной с обновлённым значением |
| `take T` | Полная передача владения | Разрешено | Разрешено (при привязке к `var`) | Эксклюзивно поглощается | Переходит в состояние `Moved` (повторный доступ запрещён — `E0201`) |

### Ключевые правила Access Capabilities:
1. **Закон эксклюзивности:** в любой момент выполнения для одного объекта (или пересекающегося пути поля `obj.field`) может существовать либо произвольное количество доступов `read`, либо ровно один доступ `write`.
2. **Раздельный доступ к полям (Field-Disjoint Projection):** компилятор отслеживает пути доступа с точностью до полей структуры. Одновременная передача `driver.name` как `read` и `driver.balance` как `write` полностью разрешена, так как пути полей не пересекаются.
3. **Запрет сохранения временных заимствований:** параметры `read T` и `write T` являются правами доступа второго класса (second-class capabilities) — их нельзя сохранить в глобальную переменную или отправить в откреплённый поток.

## 24. AMA — APS Adaptive Memory Architecture

Подробная математическая формализация приведена в отдельном документе `spec/AMA_SPEC.md`. Краткая сводка четырёх уровней AMA:
1. **Local Memory:** компилятор выполняет Escape Analysis. Если объект не возвращается из функции и его размер фиксирован, он размещается на стеке без обращения к системному аллокатору.
2. **Managed Ownership:** для объектов в куче строится ориентированный граф владения на MIR CFG. Компилятор автоматически вставляет вызовы деструкторов и освобождения памяти сразу после последнего использования владельца или при выходе из области видимости на всех путях выполнения.
3. **Region Memory:** синтаксическая конструкция `region arena { ... }` создаёт локальную арену памяти. Все объекты, выделенные в `arena`, освобождаются одной операцией перемещения указателя при выходе из блока `region`. Компилятор гарантирует, что ни одна ссылка на объект внутри `arena` не покинет блок `region` (`E0303`).
4. **Shared Immutable Memory:** функция `share(value)` переводит объект в глубоко неизменяемое разделяемое состояние `Shared<T>`, которое можно безопасно передавать между любым количеством потоков и асинхронных задач.

## 25. Async/Await

Асинхронное программирование в APS построено на безстековых конечных автоматах (stackless coroutines / state machines), компилируемых без скрытых аллокаций на каждый `await`:
```aps
async fn fetch_balance(user_id: i64) -> i64 {
    // асинхронная операция
    return 1500
}

async fn process_user(id: i64) -> i64 {
    let bal = await fetch_balance(id)
    return bal + 100
}
```
- **Структурированная асинхронность (Structured Concurrency):** дочерние асинхронные задачи запускаются в рамках области `task_scope`, которая гарантирует завершение всех порождённых задач до выхода из родительского блока. Благодаря этому задачи внутри `task_scope` могут безопасно читать данные `read` родительского кадра без риска use-after-free.
- Откреплённые задачи (`spawn`) могут захватывать только владеющие значения (`take`) или разделяемые неизменяемые данные (`Shared<T>`).

## 26. Многопоточность

Модель многопоточности APS исключает гонки данных (data races) в безопасном коде на уровне системы типов и анализатора AMA:
- **Потоки ОС (`std.thread`):** создание нативных потоков с передачей данных по владению (`take`) или через `Shared<T>`.
- **Каналы (`std.sync.Channel<T>`):** типизированные очереди сообщений для передачи владения объектами между потоками (при отправке `tx.send(take msg)` отправитель мгновенно теряет доступ к `msg`, исключая одновременный доступ).
- **Мьютексы (`std.sync.Mutex<T>`):** данные защищены внутри контейнера `Mutex<T>`; получить доступ `write T` можно только через захват блокировки `lock()`.
- **Атомарные типы (`std.sync.AtomicI64`, `AtomicBool`):** низкоуровневые примитивы синхронизации с упорядочиванием памяти (`SeqCst`, `Acquire`, `Release`).

## 27. FFI (Взаимодействие с внешним кодом)

APS обеспечивает прямой вызов функций с C ABI без накладных расходов на маршалинг:
```aps
extern "C" {
    fn puts(s: ptr<u8>) -> i32
    fn abs(x: i32) -> i32
}

fn safe_abs(x: i32) -> i32 {
    unsafe {
        return abs(x)
    }
}
```
Правила безопасности FFI:
1. Любой вызов внешней функции `extern "C"` или разыменование сырого указателя `ptr<T>` вне блока `unsafe { ... }` запрещены (`E0601`, `E0603`).
2. В сигнатурах `extern "C"` разрешены только FFI-совместимые типы с фиксированным C-представлением (`i8..i64`, `u8..u64`, `f32`, `f64`, `bool`, `ptr<T>`, `@repr(C) struct`).
3. Передача управляемых объектов APS во внешний C-код не освобождает их автоматически внутри C; граница владения должна быть явно зафиксирована.

## 28. Компиляция

Конвейер компиляции APS (`aps build` / `aps run`) состоит из строго разделённых этапов:
1. **Lexer (`compiler/lexer`):** преобразование потока символов UTF-8 в поток токенов с точными координатами (`Span { line, col, start, end }`).
2. **Parser (`compiler/parser`):** рекурсивный спуск с операторным приоритетом (Pratt parsing), строящий типизированное синтаксическое дерево (`AST`).
3. **Semantic Analysis (`compiler/semantic`):** разрешение модулей, таблиц символов, областей видимости и проверка базовых структурных инвариантов.
4. **Type Checker (`compiler/types`):** двунаправленный вывод типов (Bidirectional Type Inference), унификация обобщённых типов и проверка совместимости операций.
5. **AMA Analyzer (`compiler/ama`):** построение графа владения, проверка прав доступа `read`/`write`/`take`, анализ непересекающихся полей, Escape Analysis для регионов и расчёт точек автоматического освобождения памяти.
6. **HIR (`compiler/hir`):** высокоуровневое представление с полностью разрешёнными типами и десахаризованными конструкциями (`for`, `+=`, методы `impl`).
7. **MIR (`compiler/mir`):** представление в виде графа базовых блоков (Control Flow Graph) с явными инструкциями `Drop` / `RegionEnd`, вставленными движком AMA.
8. **APS IR (`compiler/ir`) и Optimizer (`compiler/optimize`):** платформенно-независимое трехадресное SSA-подобное представление, над которым выполняются оптимизации APS (Constant Folding, Dead Code Elimination, Inlining, CSE, Loop Invariant Code Motion, Escape Promotion).
9. **LLVM Backend (`compiler/codegen`):** генерация строго типизированного текста/модуля LLVM IR (`.ll`) и вызов системного оптимизирующего компилятора LLVM (`clang`) для получения нативного машинного исполняемого файла (`.exe` на Windows, ELF на Linux, Mach-O на macOS).

## 29. Runtime

Отсутствие сборщика мусора в APS **не означает отсутствие рантайма**. APS включает компактный детерминированный рантайм (`runtime/`), предоставляющий:
- Быстрый системный аллокатор кучи и линейный аллокатор регионов (`aps_alloc`, `aps_free`, `aps_region_create`, `aps_region_alloc`, `aps_region_destroy`).
- Поддержку строк UTF-8 и динамических массивов (`aps_string_concat`, `aps_string_eq`, `aps_vec_*`).
- Кроссплатформенный ввод-вывод в консоль, файлы и сетевые сокеты.
- Примитивы потоков ОС и планировщик задач.
- Обработчик фатальных паник с выводом диагностического сообщения и кода возврата.

Рантайм не запускает фоновых потоков сборки мусора и имеет полностью предсказуемое время выполнения.

## 30. Поведение программы при ошибках

В APS ошибки делятся на две категории:
1. **Ожидаемые (восстановимые) ошибки:** ошибки ввода-вывода, парсинга, сети, отсутствия ключа. Обрабатываются исключительно через `Result<T, E>` и `Option<T>`.
2. **Невосстановимые нарушения инвариантов (Panics):** выход за границы массива (`R0001`), целочисленное деление на ноль (`R0002`), явный вызов `panic("сообщение")` (`R0003`) или исчерпание системной памяти (`Out of Memory`). При возникновении паники программа немедленно печатает точное место и причину сбоя в `stderr` и детерминированно завершает процесс с ненулевым кодом возврата (`101`), предотвращая повреждение памяти или продолжение работы в некорректном состоянии.

## 31. Критический анализ спецификации и устранение противоречий

Перед переходом к реализации компилятора проведён внутренний аудит спецификации:

1. **Проблема 1: Конфликт между опциональными `;` и многострочными выражениями.**
   - *Анализ:* Если перевод строки всегда завершает инструкцию, выражение вида `let x = a + \n b` могло бы оборваться после `+`.
   - *Решение в спецификации:* Перевод строки завершает инструкцию **только** после токенов, способных заканчивать выражение (идентификаторы, литералы, `)`, `]`, `}`, `return`, `break`, `continue`). Если строка заканчивается бинарным оператором (`+`, `-`, `*`, `/`, `=`, `,`, `{`, `(`), парсер продолжает разбор выражения на следующей строке.
2. **Проблема 2: Передача копируемых типов (`i64`, `bool`) и модификаторы `read`/`take`.**
   - *Анализ:* Требовать писать `read i64` или `take i64` для чисел неэргономично.
   - *Решение в спецификации:* Примитивные типы (`i8..i64`, `u8..u64`, `f32`, `f64`, `bool`, `char`) обладают свойством `Copy` и по умолчанию передаются по значению (копированием регистров). Если для примитива явно указан `write i64`, он передаётся по изменяемому указателю, позволяя функции изменить числовую переменную вызывающего кода.
3. **Проблема 3: Модификация поля структуры, полученной через `read Struct`.**
   - *Анализ:* Что если структура `Driver` содержит вложенную структуру, и программист пытается изменить вложенное поле через `read Driver`?
   - *Решение в спецификации:* Права доступа `read` в APS являются **глубокими (транзитивными)**: через `read T` все поля и вложенные структуры также доступны исключительно в режиме `read`. Любая попытка записи на любой глубине вложенности блокируется ошибкой `E0042`.
