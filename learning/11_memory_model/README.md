# Глава 11: Физическая Память, Аппаратные Кэши и Модель Памяти в APS

Чтобы писать действительно быстрый системный код, инженер обязан понимать, как устроена физическая память современного компьютера. В этой главе мы рассмотрим аппаратную иерархию памяти и то, как архитектурные решения APS согласуются с микроархитектурой процессоров x86-64 и ARM64.

---

## 1. Аппаратная пирамида памяти: пропасть между CPU и DRAM

Частота современных процессоров достигает 4–5 ГГц (один такт занимает $\approx 0.2$ нс). Однако оперативная память (DRAM) работает значительно медленнее: обращение к ней занимает $60 - 100$ нс (300–500 тактов процессора!).

```
                ┌───────────────┐
                │   Регистры    │   0.5 нс (0-1 такт)
                ├───────────────┤
                │   L1D Кэш     │   1 нс (4-5 тактов, 32-64 КБ)
                ├───────────────┤
                │   L2 Кэш      │   3-4 нс (14 тактов, 512 КБ-1 МБ)
                ├───────────────┤
                │   L3 Кэш      │   10-15 нс (40-50 тактов, 16-96 МБ)
                ├───────────────┤
                │  DRAM (ОЗУ)   │   60-100 нс (300-500 тактов CPU!)
                └───────────────┘
```

Когда процессор запрашивает данные, которых нет в кэше (Cache Miss), выполнение конвейера инструкций останавливается. Поэтому **локальность данных важнее сложности алгоритма**!

---

## 2. Строка кэша (Cache Line) и Ложное Разделение (False Sharing)

Процессор никогда не считывает из оперативной памяти отдельные байты: данные загружаются блоками ровно по **64 байта** (Cache Line).

### Проблема ложного разделения в многопоточности:
Если два разных ядра процессора параллельно изменяют две независимые переменные, случайно оказавшиеся на одной 64-байтной строке кэша, контроллер когерентности кэшей (MESI/MOESI) будет непрерывно сбрасывать кэши обоих ядер (Cache Bouncing), замедляя программу в десятки раз!

В APS системные структуры данных и примитивы синхронизации (`Mutex`, каналы) автоматически выравниваются по границе 64 байт (`#[repr(align(64))]`), гарантируя отсутствие ложного разделения.

---

## 3. Стек против Кучи: почему стек быстрее

1. **Стековая память:**
   - Локальна для каждого потока выполнения.
   - Аллокация — это всего одна процессорная инструкция `sub rsp, N`.
   - Деаллокация — `add rsp, N`.
   - Память верхушки стека практически всегда находится в самом быстром L1-кэше процессора.
2. **Кучевая память (Heap):**
   - Глобальна для всего процесса.
   - Требует блокировок аллокатора при одновременных запросах из разных потоков.
   - Приводит к фрагментации памяти и промахам TLB (Translation Lookaside Buffer).

## 4. Сравнение подходов к управлению памятью

| Критерий | C / C++ (Ручной) | Go / Java / C# (GC) | Rust (Borrow Checker) | APS (AMA) |
|---|---|---|---|---|
| **Безопасность памяти** | ❌ 70% уязвимостей — UAF, buffer overflow |  Безопасно |  Безопасно |  Безопасно (доказано на стадии сборки) |
| **Паузы выполнения** |  0 | ❌ Паузы Stop-the-World, всплески p99 latency |  0 |  0 |
| **Скорость аллокации графов** | Медленно (`malloc`) | Быстро при создании, медленно при сборке | Сложно (нужны `Rc<RefCell<T>>` или арены) | **Сверхбыстро** ($O(1)$ Region Bump Arena) |
| **Простота синтаксиса** | Средняя | Высокая | ❌ Высокая кривая обучаемости (`'a`, `&mut`) | **Высокая** (`read`, `write`, `take`, `region`) |
