# Справочник: AMA (APS Adaptive Memory Architecture)

**AMA (APS Adaptive Memory Architecture)** — это гибридная 4-уровневая архитектура управления памятью языка APS, обеспечивающая 100% математически доказуемую безопасность памяти на этапе компиляции без накладных расходов сборщика мусора (Zero Garbage Collection).

---

## 1. Четыре уровня памяти AMA

```
                     ┌────────────────────────┐
                     │ 1. Local Stack Memory  │  (Zero-allocation, O(1))
                     └───────────┬────────────┘
                                 │
                     ┌───────────▼────────────┐
                     │ 2. Managed Ownership   │  (Move / Take, RAII, Defer)
                     └───────────┬────────────┘
                                 │
                     ┌───────────▼────────────┐
                     │ 3. Region Memory       │  (O(1) Bump Arena, Group Free)
                     └───────────┬────────────┘
                                 │
                     ┌───────────▼────────────┐
                     │ 4. Shared Immutable    │  (Lock-free Data Sharing, Freeze)
                     └────────────────────────┘
```

| Уровень | Назначение | Механизм аллокации | Механизм освобождения | Накладные расходы |
|---|---|---|---|---|
| **Уровень 1: Local Stack** | Локальные скалярные переменные, кортежи, примитивы | Сдвиг указателя стека `RSP` | Автоматически при выходе из стекового фрейма функции | **0 нс** |
| **Уровень 2: Managed Ownership** | Динамические строки `String`, векторы `Vector<T>`, файлы | Аллокация кучи через системный рантайм | Автоматический деструктор в точке потери области видимости | **0 сборки мусора** |
| **Уровень 3: Region Memory** | Графы, деревья, AST-узлы, сетевые запросы | $O(1)$ bump-указатель арены (`blk.used += size`) | Мгновенный сброс всей арены за $O(1)$ при выходе из блока `region` | **В 18.3 раза быстрее malloc!** |
| **Уровень 4: Shared Immutable** | Глобальные конфигурации, потокобезопасные кэши | Оператор `share` замораживает объект навсегда | Атомарный счётчик ссылок `Arc<T>` или статический сегмент | **Потокобезопасно без Mutex** |

## 2. Разрешения доступа (Access Capabilities)

APS формализует доступ к памяти через три ключевых слова-разрешения:

```aps
read T   // Иммутабельное заимствование (Shared Read)
write T  // Эксклюзивное изменяемое заимствование (Exclusive Write)
take T   // Передача полного владения (Ownership Transfer / Move)
```

### Фундаментальный инвариант эксклюзивности AMA:
В любой точке выполнения программы для любого участка памяти верно одно из двух:
$$\forall x \in \text{Memory}: \quad \big(\text{Count}(\text{read}(x)) \ge 1 \land \text{Count}(\text{write}(x)) = 0\big) \quad \oplus \quad \big(\text{Count}(\text{write}(x)) = 1 \land \text{Count}(\text{read}(x)) = 0\big)$$
*Либо произвольное число одновременных читателей (`read`), либо ровно один эксклюзивный писатель (`write`). Одновременное чтение и запись строго запрещены!*

## 3. Таблица ошибок памяти AMA

| Код ошибки | Описание нарушения | Пример некорректного кода |
|---|---|---|
| **`E0042`** | Попытка изменения неизменяемой переменной или параметра с правом `read` | `let x = 10; x = 20;` или `fn f(d: read Data) { d.v = 1; }` |
| **`E0201`** | Использование значения после перемещения владения (Use-After-Move) | `let a = String::from("hi"); let b = take a; print(a);` |
| **`E0202`** | Двойное освобождение или повторный перенос (Double-Move) | `consume(take obj); consume(take obj);` |
| **`E0203`** | Попытка забрать владение из ссылки | `fn f(d: write Data) { let my_data = take *d; }` |
| **`E0302`** | Конфликт заимствования (одновременные `read` и `write`) | `let r = read list; let w = write list; w.push(1); print(r.len());` |
| **`E0303`** | Утечка ссылки из региона арены (Region Escape) | `var outer: &Node; region arena { outer = arena.alloc(Node); }` |
| **`E0401`** | Захват непотокобезопасного объекта в параллельную задачу | `spawn { local_data.push(1); };` |
| **`E0601`** | Вызов низкоуровневой FFI-функции вне блока `unsafe` | `puts("hello");` вместо `unsafe { puts("hello"); }` |

## 4. Заморозка объектов в Shared Immutable (`share`)

```aps
var builder = ConfigBuilder::new();
builder.set_timeout(30);
builder.set_max_retries(5);

// Заморозка: builder больше не может быть изменён нигде в программе!
let app_config: shared Config = share builder.build();

// Теперь app_config можно безопасно передавать в сотни потоков spawn без Mutex:
spawn {
    worker_task(app_config);
};
```
