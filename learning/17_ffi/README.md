# Глава 17: Системная интероперабельность и C FFI в APS

APS спроектирован так, чтобы бесшовно интегрироваться в существующую инфраструктуру программного обеспечения, использовать миллионы строк проверенных C-библиотек (OpenSSL, SQLite, zlib, libuv) и вызывать системные функции Windows Win32 API и POSIX libc.

---

## 1. Объявление внешних C-функций: `extern "C"`

Для подключения внешней функции используется конструкция `extern "C"` без реализации тела функции:

```aps
extern "C" {
    fn puts(str: *const u8) -> i32;
    fn strlen(str: *const u8) -> usize;
    fn malloc(size: usize) -> *mut ();
    fn free(ptr: *mut ());
}
```

---

## 2. Изоляция опасных операций: блок `unsafe`

Политика безопасности APS гласит: *«Любая операция, инварианты которой компилятор не может доказать математически, обязана быть явно изолирована в блоке `unsafe`»*.

Попытка вызвать `puts` в обычном безопасном коде приведёт к ошибке компилятора:
```
error[E0601]: call to foreign C function 'puts' requires an unsafe block
```

### Корректный вызов в блоке `unsafe`:
```aps
fn print_via_c() {
    let message = "Привет из си-библиотеки libc!\0";
    unsafe {
        puts(message.as_ptr());
    }
}
```

---

## 3. Совместимость структур данных (`repr(C)`)

Чтобы структура APS могла напрямую передаваться в C-библиотеку без маршалинга, порядок и выравнивание её полей должны строго соответствовать стандарту платформенного C ABI:

```aps
#[repr(C)]
pub struct TimeVal {
    pub tv_sec: i64,
    pub tv_usec: i64,
}

extern "C" {
    fn gettimeofday(tv: *mut TimeVal, tz: *mut ()) -> i32;
}
```

---

## 4. Экспорт функций APS для использования в C/C++

APS может компилироваться в статическую (`.lib` / `.a`) или динамическую библиотеку (`.dll` / `.so`), экспортируя функции для вызова из других языков:

```aps
#[no_mangle]
pub extern "C" fn aps_fast_hash(data: *const u8, len: usize) -> u64 {
    // Внутри выполняется безопасный проверенный код на APS
    let slice = unsafe { std::slice::from_raw_parts(data, len) };
    std::crypto::sha256_scalar(slice)
}
```
Это позволяет постепенно переписывать критические по скорости или безопасности компоненты существующих C/C++ проектов на APS без переписывания всей системы!
