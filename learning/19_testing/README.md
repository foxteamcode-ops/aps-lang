# Глава 19: Тестирование, Верификация и Бенчмаркинг в APS

APS включает в себя встроенную систему тестирования первого класса (First-Class Testing), не требующую подключения сторонних тестовых библиотек или фреймворков.

---

## 1. Написание модульных тестов: аннотация `#[test]`

Тесты объявляются непосредственно рядом с исходным кодом модуля с помощью атрибута `#[test]`:

```aps
fn add(a: i64, b: i64) -> i64 {
    a + b
}

#[test]
fn test_addition_positive() {
    let result = add(2, 3);
    assert_eq(result, 5);
}

#[test]
fn test_addition_negative() {
    let result = add(-10, 5);
    assert_eq(result, -5);
}
```

---

## 2. Стандартные макросы проверок (Assertions)

| Макрос | Назначение | Поведение при сбое |
|---|---|---|
| `assert_true(cond)` | Проверка условия на истинность | Завершает тест с выводом файла и строки |
| `assert_false(cond)` | Проверка условия на ложность | Завершает тест с выводом файла и строки |
| `assert_eq(a, b)` | Проверка на равенство значений | Выводит ожидаемое (`left`) и фактическое (`right`) значения |
| `assert_ne(a, b)` | Проверка на неравенство | Выводит ошибку при совпадении значений |

---

## 3. Запуск тестов через CLI

Команда `aps test` автоматически сканирует проект, находит все функции с атрибутом `#[test]`, компилирует тестовый бинарный раннер и запускает тесты параллельно:

```bash
$ aps test
test tests/math_test.aps ... ok
test tests/string_test.aps ... ok
test tests/network_test.aps ... ok

test result: ok. 3 passed; 0 failed
```

---

## 4. Написание бенчмарков: `#[bench]`

Для микропрофилирования критических функций используется атрибут `#[bench]`:

```aps
#[bench]
fn bench_hash_calculation(b: write Bencher) {
    let payload = "тестовая_нагрузка_для_бенчмарка";
    b.iter(|| {
        std::crypto::sha256(payload)
    });
}
```

Запуск бенчмарков через `aps bench`:
```bash
$ aps bench
bench_hash_calculation ... 14.2 ns/iter (+/- 0.3)
```
Раннер бенчмарков автоматически отслеживает время разогрева (Warmup), количество итераций и вычисляет стандартное отклонение.
