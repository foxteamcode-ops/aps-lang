# Глава 06: Функции, Права Доступа AMA и Замыкания в APS

Функции в APS спроектированы так, чтобы сочетать выразительность функциональных языков с производительностью системных ассемблерных вызовов.

---

## 1. Объявление и сигнатура функций

```aps
fn calculate_tax(income: f64, rate: f64) -> f64 {
    income * rate
}
```

- Ключевое слово `fn`.
- Параметры строго типизированы: `имя: Тип`.
- Возвращаемый тип указывается через `->`. Если функция ничего не возвращает, тип опускается (тип `()`).
- Последнее выражение функции без точки с запятой является возвращаемым значением.

---

## 2. Права доступа AMA в параметрах (Capabilities)

В APS передача параметров в функцию явно определяет, что вызываемая функция может делать с объектом:

### 2.1. Чтение по ссылке (`read T`)
Функция получает доступ к объекту только для чтения. Исходный объект вызывающей стороны гарантированно не изменится и не будет освобождён:
```aps
fn print_profile(user: read User) {
    print("Имя: " + user.name);
    // user.balance = 0; // ОШИБКА E0042: Нельзя модифицировать read-ссылку!
}
```

### 2.2. Изменение по ссылке (`write T`)
Функция получает эксклюзивное право модифицировать объект. На время вызова другие потоки или ссылки не могут читать или писать в этот объект:
```aps
fn add_bonus(user: write User, bonus: i64) {
    user.balance += bonus;
}
```

### 2.3. Передача владения (`take T`)
Функция поглощает объект (Move Semantics). Вызывающая сторона теряет к нему доступ:
```aps
fn archive_account(user: take User) {
    save_to_archive(user);
    // user уничтожается детерминированно в конце этой функции
}
```

## 3. Функции первого класса и Замыкания (Closures)

Функции в APS могут сохраняться в переменные, передаваться как аргументы и возвращаться из других функций:

```aps
// Определение типа функции: fn(i64, i64) -> i64
let operation: fn(i64, i64) -> i64 = |a, b| a * b;
let result = operation(6, 7); // 42

// Использование замыканий с захватом переменных
let factor = 10;
let multiplier = |x: i64| x * factor;

print(multiplier(5)); // 50
```

## 4. Оптимизация хвостовой рекурсии (TCO)

Если вызов функции в рекурсивном алгоритме является последним выражением, компилятор APS гарантированно трансформирует его в безусловный скалярный цикл на уровне LLVM IR, предотвращая переполнение стека (`Stack Overflow`):

```aps
fn factorial_tail(n: i64, acc: i64) -> i64 {
    if n <= 1 {
        acc
    } else {
        factorial_tail(n - 1, acc * n) // Оптимизируется в машинный цикл!
    }
}
```
Такой вызов выполняется со сложностью по памяти $O(1)$ в стеке!
