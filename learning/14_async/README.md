# Глава 14: Асинхронное программирование и Реактор Событий в APS

Для сетевых сервисов, обслуживающих сотни тысяч одновременных подключений (C100k / C1000k), создание отдельного системного потока на каждое соединение неэффективно из-за затрат памяти на стеки потоков ($1-8$ МБ на поток) и переключение контекста ядра ОС.

В этой главе мы изучим асинхронную модель APS на основе **безстековых корутин (Stackless Coroutines)** и кооперативной многозадачности.

---

## 1. Как устроен `async/await` в APS

Когда функция объявляется с ключевым словом `async`:
```aps
async fn fetch_user(id: u64) -> Result<User, NetworkError> {
    let raw_data = http_get("/users/" + id.to_string()).await?;
    let user = parse_json(raw_data)?;
    Ok(user)
}
```

Компилятор APS выполняет трансформацию функции в конечный автомат (State Machine):
1. Локальные переменные, сохраняющие состояние между вызовами `.await`, упаковываются в плоскую структуру-фрейм задачи.
2. Каждый вызов `.await` становится точкой приостановки (Yield Point).
3. Размер фрейма задачи составляет всего **несколько сотен байт**, что позволяет одновременно держать в памяти миллионы активных задач!

## 2. Архитектура Асинхронного Реактора (Event Loop)

Рантайм `std::async` использует нативные системные мультиплексоры ядра:
- **Windows:** I/O Completion Ports (IOCP)
- **Linux:** `epoll` и `io_uring`
- **macOS / BSD:** `kqueue`

```
┌────────────────────────────────────────────────────────┐
│                  Асинхронный Рантайм                   │
├──────────────────────────┬─────────────────────────────┤
│  Очередь задач (Ready)   │  Системный реактор (I/O)    │
│  ┌────────────────────┐  │  ┌───────────────────────┐  │
│  │ Task 1 -> Task 2   │  │  │ IOCP / epoll / kqueue │  │
│  └────────────────────┘  │  └───────────────────────┘  │
└──────────────────────────┴─────────────────────────────┘
```

Поток выполнения никогда не блокируется в ожидании сетевого сокета: поток отдаёт процессор другим задачам, а ядро ОС уведомляет рантайм о поступлении данных.

## 3. Комбинаторы асинхронных задач: `join` и `select`

```aps
import std::async::{join, select, sleep};
import std::time::Duration;

async fn load_dashboard() {
    // Параллельное ожидание нескольких задач (Fork-Join)
    let (metrics, logs) = join(
        fetch_system_metrics(),
        fetch_recent_logs()
    ).await;

    // Гонка задачи с тайм-аутом (Timeout)
    let response = match select(fetch_heavy_data(), sleep(Duration::from_secs(3))).await {
        First(data) => data,
        Second(_) => "Таймаут запроса!",
    };
}
```
