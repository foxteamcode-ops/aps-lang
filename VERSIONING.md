# Модель версионирования и жизненный цикл APS

В проекте языка **APS (Advanced Performance Systems)** действует строгая 5-этапная модель развития и выпуска релизов:

---

## 1. Пять этапов жизненного цикла версий (Release Stages)

1. **Snapshot** (Текущий этап) — ранняя сборка разработчиков:
   * **Описание:** ключевой функционал компилятора, семантического анализатора AMA, генератора LLVM IR и рантайма готов и работает нативно на 100%, но система активно тестируется, выявляются граничные случаи и внедряются низкоуровневые оптимизации.
   * **Схема версий:** `1.0.0 snapshot v1`, `1.0.0 snapshot v2`, `1.0.0 snapshot v3`, `1.0.0 snapshot v4`, `1.0.0 snapshot v5`...
   * **Текущий статус:** `1.0.0 snapshot v2` (`1.0.0-snapshot.v2`).

2. **Alpha** — закрытое тестирование:
   * **Описание:** версия доступна по приглашениям (*invite-only*). Архитектура языка стабилизирована, тестируются реальные SDK и фреймворки.
   * **Схема версий:** `1.0.0 alpha v1`, `1.0.0 alpha v2`, `v3`...

3. **Beta** — публичное тестирование:
   * **Описание:** общедоступная версия для всех разработчиков (*public beta*). Открытое тестирование экосистемы пакетов (APM), плагинов и интеграций.
   * **Схема версий:** `1.0.0 beta v1`, `1.0.0 beta v2`, `v3`...

4. **Release** — полнофункциональный релиз:
   * **Описание:** официальная релизная сборка со стабильным синтаксисом и замороженным ABI.
   * **Схема версий:** `1.0.0 release v1`, `1.0.0 release v2`...

5. **Stable Release** — эталонная стабильная версия:
   * **Описание:** проверенная в бою, высоконадёжная корпоративная версия для долгосрочной промышленной эксплуатации (LTS).
   * **Схема версий:** `1.0.0 stable release`.

---

## 2. Правило перехода между версиями и стадиями

> [!IMPORTANT]
> **ПРАВИЛО ЗАМОРОЗКИ СТАДИИ:**  
> Проект сейчас находится на этапе **`1.0.0 snapshot v2`** (Ускорение и оптимизация).  
> Переход к последующим подверсиям (`snapshot v3`, `v4`...) или к следующим этапам (**Alpha**, **Beta**, **Release**, **Stable**) происходит **ИСКЛЮЧИТЕЛЬНО по явному указанию пользователя**!  
> Без команды пользователя проект остаётся на текущей стадии.
