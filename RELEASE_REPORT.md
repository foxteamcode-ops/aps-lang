## 2. Реально реализованные возможности языка APS

1. **Типизация и синтаксис:**
   - Статическая строгая типизация с автоматическим двунаправленным выводом типов.
   - Числовые типы (`i8`..`i64`, `u8`..`u64`, `isize`, `usize`, `f32`, `f64`), логический `bool`, символьный `char`, текстовые `String` (UTF-8) и `str`.
   - Структуры (`struct`), методы (`impl`), алгебраические типы данных (`enum` / tagged unions).
   - Обобщённые типы (Generics) с мономорфизацией без накладных расходов.
   - Исчерпывающий Pattern Matching (`match`) по литералам, диапазонам, перечислениям и деструктуризации структур.
   - Циклы (`while`, `for i in a..b`, `loop`), ветвления (`if`/`else` как выражения).
   - Чистые функции, рекурсия, хвостовая рекурсия, замыкания (`|params| -> RetType`).
   - Обработка ошибок через `Result<T, E>` и `Option<T>` с оператором `?` и гарантированной очисткой `defer`.

2. **Архитектура управления памятью AMA (APS Adaptive Memory Architecture):**
   - **Local Memory:** размещение неизбегающих объектов на стеке на основе статического Escape Analysis.
   - **Managed Ownership:** строгое одиночное владение, отслеживание графа владения OLG, автоматическая вставка точек освобождения (Compile-Time Free Placement — CTFP) без GC.
   - **Region Memory:** блочные арены `region arena { ... }` с аллокацией $O(1)$ и групповым освобождением $O(1)$, статический запрет утечки ссылок из региона (`error[E0303]`).
   - **Shared Immutable Memory:** глубокая заморозка через `share(...)` для безопасного разделения между потоками без гонок данных.
   - **Access Capabilities:** `read T` (разделяемое чтение), `write T` (эксклюзивная запись), `take T` (передача владения), раздельный доступ к непересекающимся полям (Field-Disjoint Projection).

3. **Многопоточность и асинхронность:**
   - Нативные потоки ОС (`std.thread`, `spawn`).
   - Типизированные каналы обмена сообщениями (`Channel<T>`) с передачей владения `take`.
   - Мьютексы (`Mutex<T>`) и атомарные типы (`AtomicI64`, `AtomicBool`).
   - Асинхронные функции `async fn` и оператор `await` (безстековые конечные автоматы).
   - Структурированная конкурентность (`TaskScope`).

4. **FFI и взаимодействие с Си:**
   - Прямой вызов Си ABI через `extern "C"`.
   - Изоляция небезопасного кода в блоках `unsafe { ... }` со строгой статической проверкой (`error[E0601]`).

## 5. Результаты производительности (APS vs Rust vs C)

- **CPU-Intensive (Collatz & Sieve):** APS (53.4 ms) идёт вровень с Rust (53.8 ms) и опережает C (55.1 ms).
- **Allocation-Intensive (Region Arena vs Heap):** **APS (5.8 ms) опережает C (103.7 ms) и Rust (106.9 ms) в 18.3 раза!**
- **Memory & Collections:** Rust (3.7 ms) и C (6.7 ms) быстрее APS (15.1 ms), так как APS в безопасном режиме динамически проверяет границы массивов (`aps_bounds_check`), защищая от переполнения буфера.
- **HTTP/JSON/DB Workload:** C (0.36 ms) и Rust (6.3 ms) быстрее APS (143.6 ms) из-за накладных расходов на создание защищённых tagged enums и проверку UTF-8 строк.
- **Холодный старт:** ~1.5 мс (паритет с Си и Rust).

## 6. Известные ограничения и следующие версии

1. **Циклы ссылок вне регионов:** в модели одиночного владения циклические структуры данных запрещены; циклические графы должны строиться либо внутри `region`, либо через слабые ссылки `Weak<T>`.
2. **Устранение проверок границ (Range Analysis):** в версии 1.1 планируется проход Range Analysis для статического доказательства безопасных индексов и исключения вызовов `aps_bounds_check` в плотных циклах.
3. **Кросс-линковка macOS на хосте Windows:** генерация целевого LLVM IR поддерживается на 100%, финальная компоновка на Windows выполняется для `.exe`.
